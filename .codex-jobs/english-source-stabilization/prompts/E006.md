# Job E006: FAQ URL-Backed Attachment Verification

## Goal

Recheck FAQ document-format attachment URLs and confirm URL-backed FAQ attachment omissions remain zero.

## Scope

- Source inputs: `semantic-coverage/doc-mapping.tsv`, S031 attachment evidence, `faq/Home`, and `FAQE/Home`.
- Evidence target: `faq` rows in `source-stabilization/url-backed-attachments.tsv`.
- Document extensions: `.pdf`, `.ppt`, `.pptx`, `.doc`, `.docx`, `.xls`, `.xlsx`, `.zip`.
- Do not rewrite existing `docs.altibase.com` URLs.

## Required Work

1. Run the worktree handoff check from the shared addendum.
2. Use FAQ mappings in `semantic-coverage/doc-mapping.tsv` and S031 attachment evidence as the starting point.
3. Verify `faq/Home` URL-backed document-format attachments are preserved in mapped `FAQE/Home` targets.
4. Record rows with the exact schema from `workflow-requirements.md` and `scope` value `faq`. On rerun, replace existing `faq` rows and preserve any `technical` rows.
5. If a URL-backed omission is found and the correct URL is present in the Korean source, add it to the mapped English target and update `manifest.json` metadata.
6. If any URL cannot be safely resolved, mark `needs_recheck`.
7. Run standard verification.
8. Commit the result with message `Verify FAQ source attachments`.

## Acceptance Criteria

- `source-stabilization/url-backed-attachments.tsv` contains FAQ attachment verification rows without overwriting technical rows.
- URL-backed FAQ document-format attachment omissions are zero unless E009 must decide `RECHECK_REQUIRED`.
- Existing source URLs remain unchanged except for adding a missing preserved source URL.
- Standard verification passes and project files are clean after the commit.
