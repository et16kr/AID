# Job G004: Optional audit bundle and upload handoff

## Goal

Create the optional second audit bundle plus upload instructions, manifest, and GPT configuration text for customer-facing use.

## Scope

Work only on optional audit packaging and GPT upload handoff files.

You may edit:

- `llm-reference/gpts-upload/build-gpts-knowledge-bundles.py`
- `llm-reference/gpts-upload/Altibase_GPT_Knowledge_Audit.md`
- `llm-reference/gpts-upload/GPTS_INSTRUCTIONS.txt`
- `llm-reference/gpts-upload/UPLOAD_MANIFEST.tsv`
- `llm-reference/gpts-upload/README.md`

## Required Steps

1. Confirm that the customer-facing GPT requires only `Altibase_GPT_Knowledge_Encyclopedia.md`.
2. Create or regenerate `Altibase_GPT_Knowledge_Audit.md` as the optional second file.
3. Create `GPTS_INSTRUCTIONS.txt` with copy-paste instructions for GPT configuration.
4. Create `UPLOAD_MANIFEST.tsv` with columns:
   - `file_path`
   - `upload_priority`
   - `audience`
   - `required_for_customer_answers`
   - `purpose`
   - `notes`
5. Update `README.md` with upload order and customer/internal file distinction.
6. Ensure the audit file is not described as required for normal customer answers.
7. Run verification.
8. Review the final diff.
9. Commit the completed job with a focused message.

## Acceptance Criteria

- `Altibase_GPT_Knowledge_Audit.md` exists or the job documents why it is intentionally skipped.
- `GPTS_INSTRUCTIONS.txt` exists and is directly usable in GPT configuration.
- `UPLOAD_MANIFEST.tsv` exists and clearly marks the encyclopedia as required and audit as optional.
- Customer-facing upload requires no more than 1 Altibase reference file.
- Internal upload requires no more than 2 Altibase reference files.
- `python3 llm-reference/gpts-upload/build-gpts-knowledge-bundles.py` passes if the script owns the audit file.
- `python3 -m json.tool manifest.json >/tmp/aid-manifest-check.json` passes.
- `git diff --check` passes.
- The job result is committed, and project files are clean after the commit.
