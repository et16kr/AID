# 2. Integrating unixODBC Manager
Source: https://docs.altibase.com/display/arch/2.+Integrating+unixODBC+Manager
Updated: 2021-02-19T13:49:13.000+0900

---

This chapter describes how to integrate with Altibase's Unix ODBC Driver.

# Setting ODBC.INI

Set the following in the environment variable of the user account.

```
export ODBCINI=/home/unixODBC/etc/odbc.ini
```

This setting means that the specified file is used as the configuration file that records ODBC driver connection information.

Write the following in /home/unixODBC/etc/odbc.ini and save.

- Example of odbc.ini

```
[ODBC Data Sources]
Altiodbc = Altibase ODBC Driver
[Altiodbc]
Driver = /altibase_home/lib/libaltibase_odbc-64bit-ul32.so
Description = Sample Altibase DSN
UserName = SYS
Password = MANAGER
ServerType = Altibase
Server = 127.0.0.1
User = SYS
Port = 20300
Database = mydb
FetchBufferSize = 64
ReadOnly = no
LongDataCompat=ON
TraceFile = /tmp/odbc.trace
Trace = 1
```

- Main setting values

| Setting Item | Setting Value | Description |
| --- | --- | --- |
| Driver | `libaltibase_odbc-64bit-ul64.so` | This driver is provided by bit type, but the important point is to check `ul64` or `ul32`. Some ODBC Managers define SQLLEN differently as 4 bytes or 8 bytes during compilation, so connection errors can occur from the connection stage. Check how SQLLEN was defined when compiling ODBC Manager. This is not the same as the 32-bit or 64-bit file distinction. |
| Driver | `libaltibase_odbc-64bit-ul32.so` | Use this 64-bit ODBC driver when SQLLEN is 4 bytes. |
| Driver | `libaltibase_odbc.so` | `libaltibase_odbc.so` is the ODBC driver used with a 32-bit unixODBC driver. This file is included in the Altibase 32-bit client package. To be precise, check the file bit with `file <FileName>`. If unixODBC is compiled as 32-bit, specify this driver. |
| LongDataCompat | ON | Set to ON when using LOB data. |

Check the SQLLEN length information above as follows.

```
shell> /home/unixODBC/bin] ./odbcinst -j
unixODBC 2.3.2
DRIVERS............: /home/unixODBC/etc/odbcinst.ini
....................
SQLULEN Size.......: 4 ( 8, if 64bit )
SQLLEN Size........: 4 ( 8, if 64bit )
SQLSETPOSIROW Size.: 2
```

The ODBC driver to use differs according to the SQLLEN size defined in unixODBC. When `SQLLEN = 4byte/32bit`, use `libaltibase_odbc-64bit-ul32.so`. When `SQLLEN = 8byte/64bit`, use `libaltibase_odbc-64bit-ul64.so`.

# Testing ODBC Connection

When the setting is completed as above, perform the following in the directory where the unixODBC Manager is installed.

```
Shell> cd /home/unixODBC/bin
Shell> ./isql Altiodbc
+---------------------------------------+
| Connected!                            |
|                                       |
| sql-statement                         |
| help [tablename]                      |
| quit                                  |
|                                       |
+---------------------------------------+
SQL>
```

If the normal connection prompt is shown as above, the DB connection is normal. In the case of AIX, `libodbcinst.so` may not be found in `LIBRARY_PATH`, or a connection may fail for a specific reason even though unixODBC was installed normally.

```
Shell> ls unixODBC-2.../odbcinst/.libs/libodbcinst.so.1
```

Check whether `libodbcinst.so.1` exists in the compiled source directory. If the corresponding `libodbcinst.so` does not exist, create a symbolic link to `libodbcinst.so.1` and place it in `LD_LIBRARY_PATH`.

In the case of SUN, the connection is possible only when the lib path of unixODBC Manager is set in LD_LIBRARY_PATH_64.

# Setting ODBC trace logs

By logging the ODBC function called from unixODBC as a file, it can be usefully used when analyzing the cause of a problem.

The following is how to configure unixODBC to record trace logs.

1. Setting ODBCINST.INI file

  ```
  [ODBC]
  TraceFile = /home/unixODBC/bin/trace.log
  Trace = Yes
  ```

  Set `odbcinst.ini` as above in the same directory path where `odbc.ini` is located. The DSN name must use `[ODBC]`. The `TraceFile` setting is the location and file name where the log contents will be recorded. Use `Trace = Yes` or `Trace = No` to select whether logging is enabled.
2. Example of unixODBC Trace output

  ```
  [ODBC][19094][1473224991.140071][__handles.c][460]
                  Exit:[SQL_SUCCESS]
                          Environment = 0x1b3a760
  [ODBC][19094][1473224991.140170][SQLAllocHandle.c][375]
                  Entry:
                          Handle Type = 2
                          Input Handle = 0x1b3a760
  [ODBC][19094][1473224991.140216][SQLAllocHandle.c][493]
                  Exit:[SQL_SUCCESS]
                          Output Handle = 0x1b3b090
  ..................................
  ```

  If the trace.log is opened, the contents of the files can be checked as above.
