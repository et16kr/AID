# 1. Backup Types
Source: https://docs.altibase.com/display/arch/1.+Backup+Types
Updated: 2025-09-23T10:03:47.000+0900

- [Logical Backup](#id-1.BackupTypes-LogicalBackup) - [Physical Backup](#id-1.BackupTypes-PhysicalBackup) - [Incremental Backup](#id-1.BackupTypes-IncrementalBackup)

The simple classification of backup types provided by Altibase is as follows. The classification criteria follow the Administrator Manual.

- Logical backup
- Physical backup
    - Online backup
    - Offline backup
- Incremental backup (supported starting from Altibase 6.3.1)

# Logical Backup

---

Logical backup is to back up database objects and data in the form of a text file that can be checked by a user using the aexport and iLoader utilities.

| Backup type | Description | Example of backup result |  |
| --- | --- | --- | --- |
| Logical Backup | aexport | aexport is a tool to support data migration between Altibase servers, but can be used for backup purposes.<br>This creates all the database object creation statements created on the Altibase server as a file named .sql.<br>It provides three methods to perform according to the purpose<br>- All database objects<br>- By database user<br>- By object | **Example of aexport execution result and file contents.**<br>```<br>$ ls -l \| head<br>Total 60<br>-rw-rw-rw- 1 eheejung eheejung  303 2019-07-12 13:15 ALL_ALT_TBL.sql<br>-rw-rw-rw- 1 eheejung eheejung    0 2019-07-12 13:15 ALL_CRT_DIR.sql<br>-rw-rw-rw- 1 eheejung eheejung    0 2019-07-12 13:15 ALL_CRT_FK.sql<br>-rw-rw-rw- 1 eheejung eheejung 1539 2019-07-12 13:15 ALL_CRT_INDEX.sql<br>-rw-rw-rw- 1 eheejung eheejung    0 2019-07-12 13:15 ALL_CRT_JOB.sql<br>-rw-rw-rw- 1 eheejung eheejung    0 2019-07-12 13:15 ALL_CRT_LIB.sql<br>-rw-rw-rw- 1 eheejung eheejung    0 2019-07-12 13:15 ALL_CRT_LINK.sql<br>-rw-rw-rw- 1 eheejung eheejung    0 2019-07-12 13:15 ALL_CRT_REP.sql<br>-rw-rw-rw- 1 eheejung eheejung    0 2019-07-12 13:15 ALL_CRT_SEQ.sql<br>...omitted...<br>$ cat ALL_CRT_TBL.sql \| head<br>connect "ALTITEST" / "ALTITEST"<br>--############################<br>--  "ALTITEST"."ORDERS"<br>--############################<br>create table "ORDERS"<br>(<br>"ONO" BIGINT,<br>"ORDER_DATE" DATE,<br>``` |
| iloader | Like aexport, this is a tool to support data migration, but it can be used for backup purposes.<br>In table units, data is backed up in a text file that can be read by users. | **Example of DEPARTMENT sample table iloader execution**<br>```<br>$ cat SYS_DEPARTMENTS.dat<br>1001,"RESEARCH DEVELOPMENT DEPT 1   ","New York       ",16<br>1002,"RESEARCH DEVELOPMENT DEPT 2   ","Sydney         ",13<br>1003,"SOLUTION DEVELOPMENT DEPT     ","Osaka          ",14<br>2001,"QUALITY ASSURANCE DEPT        ","Seoul          ",17<br>3001,"CUSTOMERS SUPPORT DEPT        ","London         ",4<br>3002,"PRESALES DEPT                 ","Peking         ",5<br>4001,"MARKETING DEPT                ","Brasilia       ",8<br>4002,"BUSINESS DEPT                 ","Palo Alto      ",7<br>``` |  |

# Physical Backup

---

Physical backup is to copy files such as data files and log anchor files that make up the Altibase server and backing them up to a different physical location.

Physical backup classified into online backup and offline backup according to the Altibase server operation status.

| Backup type | **Description** | Example of backup result |  |
| --- | --- | --- | --- |
| Physical Backup | Online backup | Performing physical backup while the Altibase server is running.<br>- There are two methods:<br>- All databases<br>- Tablespace-level | Online backup only backs up one stable memory checkpoint image file.<br>Data files in the disk temporary tablespace are not backed up.<br>```<br>$ ls -l<br>Total 2811920<br>-rw-r----- 1 tech2 tech2  727556096 2019-07-12 14:12 SYS_TBS_MEM_DATA-0-0<br>-rw-r----- 1 tech2 tech2    4300800 2019-07-12 14:12 SYS_TBS_MEM_DIC-0-0<br>-rw-r----- 1 tech2 tech2       9632 2019-07-12 14:12 loganchor0<br>-rw-r----- 1 tech2 tech2       9632 2019-07-12 14:12 loganchor1<br>-rw-r----- 1 tech2 tech2       9632 2019-07-12 14:12 loganchor2<br>-rw-r----- 1 tech2 tech2 1073750016 2019-07-12 14:13 system001.dbf<br>-rw-r----- 1 tech2 tech2 1073750016 2019-07-12 14:13 undo001.dbf<br>``` |
| Offline backup | Physical backup while the Altibase server has stopped.<br>Only full database backup is possible. | Offline backup backs up all data files.<br>```<br>[tech2@bd5 online_backup]$ ls -l<br>Total 3629032<br>-rw-r----- 1 tech2 tech2  727556096 2019-07-12 14:12 SYS_TBS_MEM_DATA-0-0<br>-rw-r----- 1 tech2 tech2  727556096 2019-07-12 14:12 SYS_TBS_MEM_DATA-1-0<br>-rw-r----- 1 tech2 tech2    4300800 2019-07-12 14:12 SYS_TBS_MEM_DIC-0-0<br>-rw-r----- 1 tech2 tech2    4300800 2019-07-12 14:12 SYS_TBS_MEM_DIC-1-0<br>-rw-r----- 1 tech2 tech2       9632 2019-07-12 14:12 loganchor0<br>-rw-r----- 1 tech2 tech2       9632 2019-07-12 14:12 loganchor1<br>-rw-r----- 1 tech2 tech2       9632 2019-07-12 14:12 loganchor2<br>-rw-r----- 1 tech2 tech2 1073750016 2019-07-12 14:13 system001.dbf<br>-rw-r----- 1 tech2 tech2  104865792 2019-07-12 15:09 temp001.dbf<br>-rw-r----- 1 tech2 tech2 1073750016 2019-07-12 14:13 undo001.dbf<br>``` |  |

# Incremental Backup

---

Incremental backup is to back up only data pages that have changed since the last incremental backup and the 'page change tracking' must be activated.

The entire database or tablespace-level can be backed up.

| Backup type | Description | Example of backup result |  |
| --- | --- | --- | --- |
| Incremental Backup | Level 0 incremental backup | Level 0 is incremental backup is similar to physical backup, but is a backup that is used for determining whether data pages have been changed. | ```<br>$ ls -l TAG_20190712_141610/<br>Total 2811924<br>-rw-r----- 1 tech2 tech2  727556096 2019-07-12 14:16 SYS_TBS_MEM_DATA-0-0_TAG_20190712_141610.ibak<br>-rw-r----- 1 tech2 tech2    4300800 2019-07-12 14:16 SYS_TBS_MEM_DIC-0-0_TAG_20190712_141610.ibak<br>-rw-r----- 1 tech2 tech2       3296 2019-07-12 14:16 backupinfo<br>-rw-r----- 1 tech2 tech2       9632 2019-07-12 14:16 loganchor0<br>-rw-r----- 1 tech2 tech2       9632 2019-07-12 14:16 loganchor1<br>-rw-r----- 1 tech2 tech2       9632 2019-07-12 14:16 loganchor2<br>-rw-r----- 1 tech2 tech2 1073750016 2019-07-12 14:16 system001.dbf_TAG_20190712_141610.ibak<br>-rw-r----- 1 tech2 tech2 1073750016 2019-07-12 14:16 undo001.dbf_TAG_20190712_141610.ibak<br>``` |
| Level 1 incremental backup | Differential incremental backup | This backs up pages that have changed since the most recently performed level 0 or level 1 incremental backup. |  |
| Cumulative incremental backup | This backs up pages that have changed since the most recently performed level 0. |  |  |
