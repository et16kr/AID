This chapter describes how to download and install `Altibase.Data.AltibaseClient.dll` for Altibase application development in a Windows ADO.NET environment. For more detailed information on ADO.NET, refer to the "Application Program Interface User's Manual".

# ADO.NET

ADO.NET is designed to provide consistent access to data sources such as XML as well as data sources connected through OLE DB and ODBC. ADO.NET components can be largely classified into .NET Framework Data Provider and DataSet. Altibase provides the components related to .NET Framework Data Provider.

| Classification | Description |
| --- | --- |
| .NET Framework Data Provider | Components designed for data manipulation and high-speed data access |
| DataSet | Components designed to allow access to data regardless of data source |

The detailed components of .NET Framework Data Provider are as follows.

![DataProvider%20%E1%84%89%E1%85%A6%E1%84%87%E1%85%AE%E1%84%80%E1%85%AE%E1%84%8C%E1%85%A9.png](https://docs.altibase.com/download/attachments/embedded-page/arch/1.%20ADO.NET%20Settings/DataProvider%20%E1%84%89%E1%85%A6%E1%84%87%E1%85%AE%E1%84%80%E1%85%AE%E1%84%8C%E1%85%A9.png?api=v2)

| Class | Description |
| --- | --- |
| Connection | Provide connectivity to data sources |
| Command | Query the connected DB |
| DataReader | Read records from the connected DB |
| DataAdapter | Fill data in the DataSet object |

The source examples later in this chapter briefly show how to use `Connection`, `Command`, `DataReader`, and `DataAdapter` provided by Altibase.

# Requirements

The environment required to use the Altibase ADO.NET provider is as follows.

- .NET Framework
  It is recommended to use the .NET Data Provider included in the Altibase HDB package with .NET Framework 2.0 or later, and Entity Framework with .NET Framework 3.5 SP1 or later.
- Different .NET Data Providers depending on the ADO.NET version
  Different library files are provided depending on the ADO.NET version, so appropriate libraries must be used for the ADO.NET version.
- Altibase CLI library
  Since the Altibase HDB .NET Data Provider connects to the database server using the Altibase CLI library, the Altibase CLI library must be installed. It is provided as standard in the Altibase HDB (server or client) package.
- DTC system service
  DTC system service must be installed to perform distributed transactions. In addition, because Altibase HDB .NET Data Provider performs distributed transactions by integrating with XA transactions, the "XA transaction" option must be activated when setting DTC.

# Downloading ADO.NET DLL

Go to [http://support.altibase.com](http://support.altibase.com/), go to "Downloads" -> "Products", download `altiadonetX.X.X_32/64bit.zip` from the LIBRARY section, and extract the ADO.NET DLLs.

In order to get the same version as the server package, use the same version in the "CLIENT" section.

(If an older version is not available on the website, contact the Q&A board at [http://support.altibase.com](http://support.altibase.com/).)

# Installing ADO.NET DLL

If installing for the first time, download and install the Windows Client package. There is no separate complicated process in the installation file, so it is not described separately in this document.

In general, after installing the package or extracting the compressed file, check that the files `Altibase.Data.AltibaseClient.dll` and `odbccli_sl.dll` exist. They are located in `%ALTIBASE_HOME%/lib` after installation.

### 3. Include odbccli_sl.dll in the dynamic library path.

Altibase's ADO.NET library always requires `odbccli_sl.dll`. Therefore, `odbccli_sl.dll` must be located in a path where it can be referenced. There are two ways to make `odbccli_sl.dll` available.

#### 3.1 To place the executable file in the folder

If odbccli_sl.dll is placed in the same folder as the executable file, it is referred to in the current path of the executable file.

#### 3.2 To add the path where the odbccli_sl.dll library is located in the environment variable PATH

This is a method of adding the path where odbccli_sl.dll is located in the environment variable PATH. If odbccli_sl.dll is in C:\altibase_client32\lib, add it to PATH as below. Visual Studio can recognize the changed contents of the PATH environment variable only after rerunning Visual Studio.

# Note

### Suitable Library must be used for the compilation bit-type of Visual Studio.

Visual Studio allows the user to select 64bit or 32bit for the application's compilation bit with an option.

![%E1%84%87%E1%85%B5%E1%84%90%E1%85%B3%E1%84%89%E1%85%A5%E1%86%AB%E1%84%90%E1%85%A2%E1%86%A8.png](https://docs.altibase.com/download/attachments/embedded-page/arch/1.%20ADO.NET%20Settings/%E1%84%87%E1%85%B5%E1%84%90%E1%85%B3%E1%84%89%E1%85%A5%E1%86%AB%E1%84%90%E1%85%A2%E1%86%A8.png?api=v2)

Use the Altibase ADO.NET library that matches the Visual Studio compilation bit type. If Visual Studio is set to compile as 32-bit, download and use `altiadonetX.X.X.X_32bit.zip` from [support.altibase.com](http://support.altibase.com/). If Visual Studio is set to 64-bit compilation mode, download and use `altiadonetX.X.X.X_64bit.zip`. If the DLL type differs from the Visual Studio bit setting, a runtime error occurs.

# Preparation Completed

After installing the two files as above, environment preparation for using the ADO.NET provider is completed.
