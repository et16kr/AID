As described in previous chapters, for each item, this chapter summarizes how the user could routinely check and find the cause of the CPU overload.

# 5.1 Step-by-step inspection method

## 5.1.1 Data collection for analysis

Collect data to determine whether the current CPU load is normal. Use OS commands and the method described in "1.1 Routine Checklist" to collect information such as Altibase hourly/daily CPU usage and transaction throughput. Then determine whether the CPU usage increase is normal because transaction throughput increased.

## 5.2 Cause analysis

### 5.2.1 Check whether it is related to the impact of application change

If there is a newly added service (application) and the operation time of the newly added service and the time of an increase in CPU load amount coincide, it is necessary to check the relevance of the newly added service.

### 5.2.2 Relevance to data increase and check whether there is any change in the query plan

Check whether CPU usage increased because access cost increased as data accumulated over time. In older Altibase versions (`6.1.1` or earlier), statistics can be collected automatically under certain conditions. If the optimizer selects and uses a plan that is less efficient than the previous query plan because statistics were updated, the increased access cost can cause CPU usage to increase.

### 5.2.3 Mismatch of DB and application character set

When the character set (`NLS_USE`) differs between the DB and the application, Altibase performance can degrade and CPU usage can increase because of internal character-set conversion.

### 5.2.4 Increase of service thread

When dedicated service threads that handle session requests increase, `sys` CPU usage may increase because the `select-poll` system call periodically checks whether requests exist.

### 5.2.5 Effect of OS environment variables

There may be changes in CPU usage depending on the OS environment variable setting. Altibase adopts a multi-threaded structure, so it is necessary to properly set the related settings for the OS configuration.

### 5.2.6 Frequent DB connection attempts

Connecting to and disconnecting from the DB consumes DB resources, and in a structure that repeatedly connects and disconnects, problematic queries are difficult to detect. Because statements cannot be prepared and reused, this can also degrade query performance.

## **5.3 Navigation with OS utility**

Altibase adopts a multi-thread structure. Therefore, it is necessary to determine whether a specific internal thread is abnormally using a lot of CPU. In this case, the CPU usage and current state of each thread can be checked with the utility provided for each OS. For more detailed information, refer to the following document.

- "Utility Guide for each OS for Problem Analysis"
