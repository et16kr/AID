# 1. Altibase Server Monitoring Overview
Source: https://docs.altibase.com/display/arch/1.+Altibase+Server+Monitoring+Overview
Updated: 2025-09-24T08:56:05.000+0900

- [Monitoring Classification](#id-1.AltibaseServerMonitoringOverview-MonitoringClassification) - [Data Dictionary](#id-1.AltibaseServerMonitoringOverview-DataDictionary) - [Monitoring Method](#id-1.AltibaseServerMonitoringOverview-MonitoringMethod)

This chapter describes the basic concepts required to monitor an Altibase server.

## Monitoring Classification

---

Altibase is a DBMS. DBMS monitoring can be classified into three categories as follows.

**This document guides users through the monitoring queries needed for 'internal monitoring'.**

- Internal Monitoring: Monitoring inside the DBMS by querying the data dictionary.
- External Monitoring: Monitoring outside the DBMS by using OS commands.
- Trace Log Monitoring: Monitoring the trace logs recorded by the DBMS.

## Data Dictionary

---

The Altibase data dictionary consists of two types that summarize and store all information about the database so that DBMS can be used efficiently.

- **Meta Table**

  These tables are created automatically at database creation time to manage database objects. They are owned by the system administrator user `SYSTEM_`, and general users can only query them with `SELECT`.
- **Performance View**

  A performance view returns Altibase internal status information at `SELECT` time, so it can be used to obtain the latest server status. Performance views are also read-only, and their prefix is `V$`.

## Monitoring Method

---

Monitoring methods commonly used in the field are as follows.

- Writing shell scripts
- Writing applications
- Using utilities
