# 4. Main Meta Tables and Performance Views Related to Replication
Source: https://docs.altibase.com/display/arch/4.+Main+Metal+Tables+and+Performance+Views+Related+to+Replication
Updated: 2025-09-24T09:01:59.000+0900

- [Main Meta Tables](#id-4.MainMetalTablesandPerformanceViewsRelatedtoReplication-MainMetaTables) - [Main Performance Views](#id-4.MainMetalTablesandPerformanceViewsRelatedtoReplication-MainPerformanceViews)

The following diagram shows the key columns in meta tables and performance views that are commonly referenced in replication monitoring join queries.

`SYS_REPL_ITEMS_` stores the column name and user name together. Therefore, `SYS_USERS_` and `SYS_TABLES_` do not need to be joined only to check the database user name and table name.

As noted earlier, replication transactions do not have session numbers or query numbers. The corresponding transaction on the replication peer server is identified through `V$REPSENDER_TRANSTBL` and `V$REPRECEIVER_TRANSTBL`.

## Main Meta Tables

- **SYS_REPLICATIONS_**

  Stores information about all replication objects, including detailed information such as the point (`XSN`) up to which the replication target server has applied replication.
- **SYS_REPL_HOSTS_**

  Stores information about replication target servers, including the server address (`HOST_IP`) and port number (`PORT_NO`).
- **SYS_REPL_ITEMS_**

  Stores information about replication target tables.

## Main Performance Views

- **V$REPSENDER**

  Shows the status of the Sender, which is the replication send thread. If the Sender is not running, this view returns no rows for it.
- **V$REPGAP**

  Shows the gap between the latest redo log serial number and the redo log serial number sent by the Sender. Because this gap indicates the synchronization level between replication target servers, it is essential for replication monitoring. This gap is measured by the Sender, so the view also returns no rows when the Sender is not running.
- **V$REPRECEIVER**

  Shows the status of the Receiver, which is the replication receive thread. If the Receiver is not running, this view returns no rows for it.
- **V$REPSENDER_TRANSTBL**

  Shows the replication transaction being executed by the Sender and identifies the corresponding transaction on the peer server. This view also returns no rows when the Sender is not running.
- **V$REPRECEIVER_TRANSTBL**

  Shows the replication transaction being executed by the Receiver and identifies the corresponding transaction on the peer server. This is an important reference when a local transaction is waiting because of a replication transaction lock. This view also returns no rows when the Receiver is not running.
