# 1. Main Meta Tables and Performance Views for Sessions, Queries, Transactions, Locks, Service Threads, and Memory DB GC
Source: https://docs.altibase.com/display/arch/1.+Main+meta+table+and+performance+views+related+to+session%2C+query%2C+transaction%2C+lock%2C+service+thread%2C+and+memory+DB+GC
Updated: 2025-09-24T08:58:45.000+0900

- [Main Meta Tables](#main-meta-tables)
- [Main Performance Views](#main-performance-views)

Users can monitor session, query, transaction, lock, service thread, and memory DB GC status in real time through meta tables and performance views. The ERD below shows the join relationships between the meta tables and performance views used by the monitoring queries.

`V$MEMGC` is marked separately because it is a performance view for memory DB GC. It has no direct relationship with the other meta tables and performance views, but it is used with specific columns in `V$TRANSACTION`.

Query execution statistics in `V$STATEMENT` are updated only when the `TIMED_STATISTICS` property is enabled (`1`). Check this property before using those statistics. The default value of `TIMED_STATISTICS` is disabled (`0`).

Replication transactions also use `V$TRANSACTION`, `V$LOCK`, and `V$LOCK_WAIT`, but they are covered separately in the replication section because replication transactions do not have session numbers or query numbers.

## **Main Meta Tables**

---

- **SYS_USERS_** stores database user information such as `USER_NAME`. It is one of the basic meta tables used by monitoring queries.
- **SYS_TABLES_** stores information about tables, including queue tables, as well as sequences and views. It is commonly joined with `SYS_USERS_` to check object information such as `TABLE_NAME`.

## **Main Performance Views**

---

- **V$SESSION** shows session information for currently connected users.
- **V$STATEMENT, V$SQLTEXT, V$PLANTEXT** provide query information and query-level statistics related to sessions. `V$STATEMENT` can be used to measure query execution time and frequency. For each session, it keeps one query executed directly and multiple prepared queries; the rows disappear when the session ends. Query text in this view is limited to 16 KB.

  If the query text exceeds 16 KB, use `V$SQLTEXT` to view the full query text. Use `V$PLANTEXT` to check the execution plan for the query.

  As noted above, query execution statistics in `V$STATEMENT` are provided only when `TIMED_STATISTICS` is enabled (`1`). The default value of `TIMED_STATISTICS` is disabled (`0`).

- **V$SERVICE_THREAD** shows service thread status. Join it with `V$SESSION` and `V$STATEMENT` to check related sessions and queries. The view is also useful by itself for service thread monitoring.
- **V$TRANSACTION, V$MEMGC**: `V$TRANSACTION` shows information about all currently executing transactions and is a primary view for lock monitoring. `V$MEMGC` shows memory DB GC information and can be used to check MVCC status associated with sessions and statements.

- **V$LOCK, V$LOCK_WAIT**: `V$LOCK` shows lock information generated during transaction execution. It is used together with `V$LOCK_WAIT`, which represents lock wait relationships.

- **V$LOCK_STATEMENT** shows the last statement executed by the transaction that acquired the current lock. It is mainly used to quickly identify the related session and statement when a lock occurs.
