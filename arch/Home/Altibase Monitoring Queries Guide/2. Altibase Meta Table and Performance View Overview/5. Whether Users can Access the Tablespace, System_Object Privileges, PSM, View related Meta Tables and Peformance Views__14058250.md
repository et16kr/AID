# 5. Meta Tables and Performance Views for Tablespace Access, Privileges, PSM, and Views
Source: https://docs.altibase.com/pages/viewpage.action?pageId=14058250
Updated: 2025-09-24T09:02:12.000+0900

- [Main Meta Tables](#main-meta-tables)

The following metadata is commonly checked during operations even though it does not usually require real-time monitoring: user access to tablespaces, system/object privileges, and schema objects such as PSM objects and views.

The following diagram shows the key columns in related meta tables and performance views that are commonly referenced in join queries.

![2.png](https://docs.altibase.com/download/attachments/embedded-page/arch/5.%20Whether%20Users%20can%20Access%20the%20Tablespace,%20System/Object%20Privileges,%20PSM,%20View%20related%20Meta%20Tables%20and%20Peformance%20Views/2.png?api=v2)

The column names that correspond to the object number column `OBJ_ID` (green) in `SYS_GRANT_OBJECT_` differ depending on the object type.

Examples include the `TABLE_ID` (red), `VIEW_ID` (red), and `PROC_OID` (purple) columns.

Most database objects have their own meta tables. Views, however, are managed together with tables, so specific information such as the view name must be checked in `SYS_TABLES_`. `SYS_VIEWS_` stores only the view compile status. Therefore, `VIEW_ID` in `SYS_VIEWS_` is the same as `TABLE_ID` in `SYS_TABLES_`.

## Main Meta Tables

- **SYS_TBS_USERS_**

  Stores the list of tablespaces that the user can access.
- **SYS_PRIVILEGES_**

  Stores privilege IDs (`PRIV_ID`) and privilege names (`PRIV_NAME`) for system privileges and object privileges.
- **SYS_GRANT_SYSTEM_**

  Stores privilege IDs (`PRIV_ID`) for system privileges granted to the user.
- **SYS_GRANT_OBJECT_**

  Stores privilege IDs (`PRIV_ID`) and object information for object privileges granted to the user. Detailed object information can be checked through the object number (`OBJ_ID`).
- **SYS_VIEWS_, SYS_VIEW_PARSE_**

  `SYS_VIEWS_` stores only the compiled state of the view. The view creation statement can be checked through `SYS_VIEW_PARSE_`.
- **SYS_PROCEDURES_, SYS_PROC_PARSE_**

  Stores detailed information about PSM objects (procedures, functions, and typesets). The creation statement for each PSM object can be checked through `SYS_PROC_PARSE_`.
