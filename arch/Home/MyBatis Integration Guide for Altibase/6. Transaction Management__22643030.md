# 6. Transaction Management
Source: https://docs.altibase.com/display/arch/6.+Transaction+Management
Updated: 2025-10-21T09:31:06.000+0900

- [Transaction Management in MyBatis](#id-6.TransactionManagement-TransactionManagementinMyBatis)

When integrating MyBatis with a database, the dataSource is specified in the <transactionManager> tag within each DB-specific <environment> under the <environments> section of the Configuration file. The database connection is then established through the SqlSessionFactory object using the <environment> id. At this time, auto-commit mode can also be configured, with the default being auto-commit enabled.

This chapter introduces various transaction management methods.

## Transaction Management in MyBatis

---

Unlike iBatis, where only one DB could be configured per configuration file, MyBatis allows multiple DBs to be configured and managed under the <environments> tag.

Each <environment> tag within <environments> configures one DB, specifying the dataSource under the <transactionManager> tag. The application programmer can manage transactions directly.

In MyBatis, there is no explicit transaction start or end. Instead, auto-commit mode can be set when configuring the SqlSessionFactory through the Configuration.

The following example shows how to configure multiple DBs in a single Configuration file. Example) mybatis-config.xml file of altibase_mybatis_MultiVersionConnection

```
…
<!-- DB connection options: UNPOOLED/POOLED/JNDI -->
<!-- transactionManager options: JDBC/MANAGED -->
<environments default="development">
<!-- connection configuration for the development alias (version 5) -->
<environment id="development">
  <transactionManager type="JDBC" />
  <dataSource type="POOLED">
    <property name="driver" value="${jdbc5.driver}" />
    <property name="url" value="${jdbc5.url}" />
    <property name="username" value="${jdbc5.username}" />
    <property name="password" value="${jdbc5.password}" />
    <property name="poolPingQuery" value="select 1 from dual"/>
      <property name="poolMaximumActiveConnections" value="100"/>
      <property name="poolMaximumIdleConnections" value="50"/>
      <property name="poolMaximumCheckoutTime" value="20000"/>
  </dataSource>
</environment>
<!-- connection configuration for the release alias (version 6 or later) -->
  <environment id="release">
    <transactionManager type="JDBC" />
    <dataSource type="POOLED">
      <property name="driver" value="${jdbc.driver}" />
      <property name="url" value="${jdbc.url}" />
      <property name="username" value="${jdbc.username}" />
      <property name="password" value="${jdbc.password}" />
      <property name="poolPingQuery" value="select 1 from dual"/>
        <property name="poolMaximumActiveConnections" value="100"/>
        <property name="poolMaximumIdleConnections" value="50"/>
        <property name="poolMaximumCheckoutTime" value="20000"/>
    </dataSource>
  </environment>
</environments>
…
```

Example) MybatisUtil.java file of altibase_mybatis_MultiVersionConnection

```
…
// Read configuration values from mybatis-config.xml
inputStream = Resources.getResourceAsStream("mybatis-config.xml");
// Create a SqlSessionFactory from the XML file. Pass the environment id as an argument to select the DB configuration.
sqlSessionFactory = new SqlSessionFactoryBuilder()build(inputStream, “release”);
// Create a SqlSession object. The argument determines whether autoCommit is enabled.
// The default is true. Passing false sets autocommit=false.
sqlSession = sqlSessionFactory.openSession(false);
…
```

To run the above altibase_mybatis_MultiVersionConnection project example, just like setting the dataSource in the Configuration file to connect with ALTIBASE, the Altibase.jar and mybatis-3.2.8.jar files are required.
