To integrate Altibase with MyBatis, set the Altibase JDBC Driver and specify a dataSource for Altibase in the configuration file.

This section explains how to obtain the Altibase JDBC Driver, how to configure the JDBC Driver, and how to set the dataSource in the configuration.

It also covers how to use the fail-over feature, how to connect to multiple versions of Altibase, and how to call stored procedures or functions.

## How to obtain the Altibase JDBC Driver

---

The JDBC driver provided by Altibase is the Altibase.jar file. This file is located in the $ALTIBASE_HOME/lib directory on the server where Altibase is installed.

Starting from Altibase version 5, both Altibase.jar and Altibase5.jar files are found in the $ALTIBASE_HOME/lib directory. Altibase.jar is the standard JDBC driver file, while Altibase5.jar is used when connecting to Altibase version 5 and earlier versions together.

Therefore, if you are connecting to a single Altibase database or to multiple Altibase instances of the same version, use the $ALTIBASE_HOME/lib/Altibase.jar file.

To ensure compatibility between the Altibase DB server and the Altibase JDBC Driver, it is necessary to check the JDBC Driver version.

You can check the Altibase JDBC Driver version by running the following command.

```
$ java –jar Altibase.jar
JDBC Driver Info : Altibase Ver = 6.3.1.2.6 for JavaVM v1.4, CMP:7.1.1, Oct  6 2014 13:54:56
```

At this time, compatibility is ensured if the cm protocol version of Altibase and the CMP of the Altibase JDBC Driver are the same.

```
$ altibase -v
version 6.3.1.2.7 X86_64_LINUX_redhat_Enterprise_ES4-64bit-6.3.1.2.7-release-GCC3.4.6
(x86_64-unknown-linux-gnu) Oct  8 2014 09:16:24, binary db version 6.2.1, meta version 6.3.1,
cm protocol version 7.1.1, replication protocol version 7.4.1
```

As the version is updated, there is a possibility that JDBC-related bugs have been fixed, so it is generally recommended to use an ALTIBASE JDBC Driver file that is either the same version as Altibase or newer.

## How to set up the JDBC Driver

---

The downloaded JDBC Driver, Altibase.jar, should be added to the classpath or placed in an appropriate directory of the web server. If you are developing with Eclipse, you can add the Altibase JDBC Driver to the project as follows: Go to Project → Properties → Java Build Path, then use the Add External JARs option to register the library.

## Connecting to Altibase by setting the DataSource in the configuration file

---

To connect to Altibase, specify the properties for Altibase inside the `<configuration>` tag of the configuration file. At this point, you can either enter the property values directly in the configuration file, or create a separate properties file and load the values from that file.

The following is an example of defining Altibase-related properties in a file named `db.properties` and then using those properties in the configuration file. Example) db.properties file for altibase_mybatis_sidu

```
jdbc.driver=Altibase.jdbc.driver.AltibaseDriver
jdbc.url=jdbc:Altibase://192.168.1.35:36492/mydb
jdbc.username=sys
jdbc.password=manager
```

The meaning of each value set in this file is as follows.

| Property | Description |
| --- | --- |
| driver | Altibase JDBC driver class name |
| URL | Connection string information for connecting to Altibase should be written in the form `jdbc:Altibase://IP:port_no/db_name`. |
| username | Database account |
| password | Database password |

example) mybatis-config.xml file of altibase_mybatis_sidu

```
<configuration>
    <properties resource="db.properties" />
	<typeAliases>
	<typeAlias type="com.altibase.sidu.model.UserVo" alias="User" />
	</typeAliases>

	<!-- DB connection options: UNPOOLED/POOLED/JNDI -->
	<!-- transactionManager options: JDBC/MANAGED -->
	<environments default="development">
		<environment id="development">
	<transactionManager type="JDBC" />
	<dataSource type="POOLED">
		<property name="driver" value="${jdbc.driver}" />
		<property name="url" value="${jdbc.url}" />
		<property name="username" value="${jdbc.username}" />
		<property name="password" value="${jdbc.password}" />
		<property name="poolPingQuery" value="select 1 from dual"/>
		<property name="poolMaximumActiveConnections" value="100"/>
		<property name="poolMaximumIdleConnections" value="50"/>
		<property name="poolMaximumCheckoutTime" value="20000"/>
	</dataSource>
	</environment>
	</environments>
	<mappers>
		<mapper resource="com/altibase/sidu/mapper/UserMapper.xml" />
	</mappers>
</configuration>
```

The driver, url, username, and password properties specified in db.properties are read and set to the dataSource properties: JDBC.Driver, JDBC.ConnectionURL, JDBC.Username, and JDBC.Password.

To run the SimpleConnection project shown in the example above, the Altibase.jar and mybatis-3.2.8.jar files are required.

## Connection using Fail-Over

---

Fail-Over has been supported since Altibase 5.3.3. To use the Fail-Over feature, include the Fail-Over related properties in the Connection URL of the dataSource.

The following is an example of connecting to Altibase using Fail-Over. The Connection URL part is defined in the db.properties file.

```
Example) db.properties file of FailOverSample
driver=Altibase.jdbc.driver.AltibaseDriver
url=jdbc:Altibase://192.168.6.224:21129/mydb?
AlternateServers=(192.168.1.35:21129)&
ConnectionRetryCount=1&ConnectionRetryDelay=1&
SessionFailOver=off&LoadBalance=off&Healthcheckduration=10& Failover_source=MESSAGE&
username=sys
password=manager
```

The Fail-Over related properties that can be defined in the Connection URL part specified in the above file are as follows.

| Property | Description |
| --- | --- |
| AlternateServer | Specifies the available servers to connect to in case of failure, written in the format IP Address1:Port1, IP Address2:Port2, ... |
| ConnectionRetryCount | The number of retry attempts when connecting to an available server fails. |
| ConnectionRetryDelay | The wait time in seconds before retrying connection after a failure to connect to an available server. |
| LoadBalance | If set to on, the initial connection attempt randomly selects from the primary server and available servers. If set to off, the initial attempt connects to the primary server, and if that fails, it tries the servers specified in AlternateServer. |
| SessionFailOver | Indicates whether to perform STF (Service Time Fail-Over). on means STF, off means CTF. CTF (Connection Time Fail-Over) detects failure at the time of DBMS connection and retries connecting to another available server. STF (Service Time Fail-Over) detects failure during service, reconnects to another available DBMS node, restores session properties, and allows the user application to continue its logic. STF only handles Fail-Over for DB connections; failed transactions must be retried by the user. |
| Healthcheckduration | Specifies the wait time before a server that experienced failover is added back to the AlternativeServer list. When connection failover occurs, the server is removed from the AlternativeServer list. After a set time, the server is re-added to the list. HealthCheckDuration determines this time in seconds. |
| Failover_source | Specifies a description sent to the server as Failover_source during failover. This information is stored in the FAILOVER_SOURCE column of the V$SESSION performance view. |

To run the above FailOverSample project, as in the section about setting the dataSource in the Configuration file to connect with Altibase, the Altibase.jar and mybatis-3.2.8.jar files are required.

## Connecting Altibase5 and previous versions simultaneously

---

From Altibase v5 onwards, a dedicated JDBC Driver (Altibase5.jar) is provided so that one application can connect to Altibase v6 and Altibase v5, or Altibase v4 simultaneously.

Using this driver, it is possible to connect between two versions of Altibase such as Altibase v6 – Altibase v5, Altibase v6 – Altibase v4, and Altibase v5.1.5 – Altibase v5.3.3.

To distinguish from the existing Altibase.jar, a separate Altibase5.jar specific for Altibase v5 is required. Also, when specifying in the dataSource, the JDBC Driver class name must be set to Altibase5.jdbc.driver.AltibaseDriver instead of the existing Altibase.jdbc.driver.AltibaseDriver.

To integrate MyBatis with different versions of Altibase, you need to write an <environment> tag for each version and let the application read the settings through the <environment> id when connecting to the DB.

One important point is that in the program, Altibase5.jdbc.driver.AltibaseDriver must be loaded first, followed by Altibase.jdbc.driver.AltibaseDriver.

Below is an example of loading drivers for two versions of ALTIBASE using Altibase.jar and Altibase5.jar files.

Example) db.properties file of altibase_mybatis_MultiVersionConnection Settings for Altibase v6 version

```
# Altibase v6 settings
jdbc.driver=Altibase.jdbc.driver.AltibaseDriver
jdbc.url=jdbc:Altibase://192.168.1.62:21020/mydb
jdbc.username=test
jdbc.password=test
```

Example) db.properties file of altibase_mybatis_MultiVersionConnection Settings for versions prior to Altibase v6

```
<environment id="release">
  <transactionManager type="JDBC" />
  <dataSource type="POOLED">
    <property name="driver" value="${jdbc.driver}" />
    <property name="url" value="${jdbc.url}" />
    <property name="username" value="${jdbc.username}" />
    <property name="password" value="${jdbc.password}" />
    <property name="poolPingQuery" value="select 1 from dual"/>
      <property name="poolMaximumActiveConnections" value="100"/>
      <property name="poolMaximumIdleConnections" value="50"/>
      <property name="poolMaximumCheckoutTime" value="20000"/>
  </dataSource>
</environment>
```

Settings for versions prior to Altibase v6

```
<environment id="development">
  <transactionManager type="JDBC" />
  <dataSource type="POOLED">
    <property name="driver" value="${jdbc5.driver}" />
    <property name="url" value="${jdbc5.url}" />
    <property name="username" value="${jdbc5.username}" />
    <property name="password" value="${jdbc5.password}" />
    <property name="poolPingQuery" value="select 1 from dual"/>
      <property name="poolMaximumActiveConnections" value="100"/>
      <property name="poolMaximumIdleConnections" value="50"/>
      <property name="poolMaximumCheckoutTime" value="20000"/>
  </dataSource>
</environment>
```

Example) MultiVersionConnectionMain.java file of altibase_mybatis_MultiVersionConnection

```
…
MultiVersionConnectionSelect multi_connection_select =
new MultiVersionConnectionSelect();

System.out.println("DB Version = " +  multi_connection_select.MultiVersionConnectionDBVersionSelect("release"));

System.out.println("DB Version = " +  multi_connection_select.MultiVersionConnectionDBVersionSelect("development"));
…
```

MultiVersionConnectionSelect.java of altibase_mybatis_MultiVersionConnection (`public String MultiVersionConnectionDBVersionSelect(String conn_type)`)

```
…
String statement = "com.altibase.multiVersionConnection.mapper.UserMapper.selectDBVersion";
res_string = MybatisUtil.getSqlSessionFactory(conn_type).selectOne(statement);
…
```

In the above MultiVersionConnectionMain.java example, to load Altibase5.jdbc.driver.AltibaseDriver before Altibase.jdbc.driver.AltibaseDriver, the id of the Altibase v5 driver’s tag, which is "release," is set as an argument. As mentioned earlier, the Altibase5.jdbc.driver.AltibaseDriver driver must be loaded first.

To run the MultiVersionConnection project included in the example, in addition to the previously used mybatis-3.2.8.jar file, the Altibase.jar and Altibase5.jar files are also required. These files are located in the lib directory inside the Altibase installation directory ($ALTIBASE_HOME). You should use the Altibase5.jar file for Altibase v5 and the Altibase.jar file for earlier versions.

- ALTIBASE 6.3.1 jar : Altibase.jar
- ALTIBASE 5.x.x.jar : Altibase5.jar

## Calling Procedures

---

When calling a stored procedure created in the DB from MyBatis, it should be configured in the Configuration file just like basic DML operations. However, the following points should be noted when using it:

- The <procedure> tag used in the previous iBatis has been removed, and procedure/function calls are determined only by statementType, so when using procedures/functions, statementType must be set to CALLABLE.
- The <parameterMap> used in the previous iBatis cannot be used.

Below is an example of selecting using a stored procedure.

Example) Procedure creation script in altibase_mybatis_procedure

```
CREATE OR REPLACE PROCEDURE PROC_SEL_TEST(usr_no IN INTEGER, res_user OUT TEST_TYPE.TEST_CUR)
as
    SQL_STMT VARCHAR(200);
BEGIN
    SQL_STMT :='SELECT user_no as userNo,
user_name as userName,
user_content as userContent,
reg_date as regDate
FROM users
WHERE user_no = ?';
    OPEN res_user FOR SQL_STMT USING usr_no;
END;
/

CREATE or replace TYPESET TEST_TYPE
AS
  TYPE TEST_CUR IS REF CURSOR;
END;
/
```

Example) UserMapper.xml (Mapper) file of altibase_mybatis_procedure

```
<select id="testSelectProc" statementType="CALLABLE" parameterType="INTEGER" resultType="User">
  { call PROC_SEL_TEST(
    #{userNo,mode=IN,jdbcType=INTEGER,javaType=INTEGER}
) }
</select>
```

By specifying the attribute statementType as CALLABLE in the <select> tag, it explicitly indicates that the request is a Procedure/Function call. The IN parameters of the called Procedure/Function are configured, and by setting the resultType to a Bean class, the results of the procedure are returned as instances of that Bean class.

At this time, the column names in the Bean class must match the column names selected from the DB for the results to be properly returned to the Bean class. To run the altibase_mybatis_procedure example, as in the section about setting the dataSource in the Configuration file to connect with Altibase, the Altibase.jar and mybatis-3.2.8.jar files are required.

## Calling Functions

---

When calling a Function created in the DB from MyBatis, it should be configured in the Configuration file just like basic DML operations. However, the following points should be noted:

- The <procedure> tag used in the previous iBatis has been removed, and procedure/function calls are determined only by statementType, so statementType must be set to CALLABLE when using Procedures/Functions.
- The <parameterMap> used in the previous iBatis cannot be used.

Below is an example of handling a Stored Function that returns a simple addition result. Although the basics are the same as Stored Procedures, the way of calling differs slightly, so it is described separately.

Example) Function creation script in altibase_mybatis_procedure

```
CREATE OR REPLACE FUNCTION sum_func
(
p_num1 IN NUMBER,
p_num2 IN NUMBER
)
RETURN NUMBER
AS
v_num NUMBER;
BEGIN
  v_num := p_num1 + p_num2;
  RETURN v_num;
  END;
/
```

Example) UserMapper.xml (Mapper) file of altibase_mybatis_procedure

```
<select id="testSelectFunc" statementType="CALLABLE" parameterType="map" resultType="INTEGER">
  { call #{resNum,mode=OUT,jdbcType=INTEGER,javaType=INTEGER} :=  SUM_FUNC(
    #{Num1,mode=IN,jdbcType=INTEGER,javaType=INTEGER},
    #{Num2,mode=IN,jdbcType=INTEGER,javaType=INTEGER}
     ) }
</select>
```

The basic configuration method is the same as for Stored Procedures, but the way Functions are called in the Mapper is different. The differences compared to calling Stored Procedures are as follows.

```
Procedure : call PROC_SEL_TEST(#{IN});
Function  : call #{OUT} := SUM_FUNC(#{IN})
```

When calling a Function from the Mapper, you must follow the format described above for the Function call to work correctly.

To run the altibase_mybatis_procedure example, as in the section about setting the dataSource in the Configuration file to connect with Altibase, the Altibase.jar and mybatis-3.2.8.jar files are required.
