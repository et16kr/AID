# 7. Considerations for MyBatis Integration
Source: https://docs.altibase.com/display/arch/7.+Considerations+for+MyBatis+Integration
Updated: 2025-10-21T09:31:34.000+0900

This chapter describes considerations when integrating Altibase with MyBatis.

## LOB Data Handling

---

In iBatis, to handle LOBs, it was necessary to explicitly specify the jdbcType as CLOB or BLOB in the Mapper file’s parameter and result settings, typically using parameterMap. However, since parameterMap is deprecated in MyBatis, you now directly specify the jdbcType on the columns being bound in the query. If jdbcType is not explicitly specified, the data will not be recognized as LOB and will cause an error.

Below is an example showing the parameterMap and resultMap settings for CLOB type data.

Example) LobMapper.xml (Mapper) file of altibase_mybatis_lob

```
<mapper namespace="com.altibase.psy.mapper.LobMapper">
<!-- LOB select, insert, update, delete Test - 2013/11/05 -->
<select id="selectBlobData" parameterType="Integer" resultType="LobVo">
	SELECT user_no as userNo, user_name as userName, blob_data as blobData, clob_data as clobData, reg_date as regDate
	FROM test_blob
	WHERE user_no = #{userNo}
</select>

<select id="selectAllBlobData"  resultType="LobVo">
	SELECT user_no as userNo, user_name as userName, blob_data as blobData, clob_data as clobData, reg_date as regDate
	FROM test_blob
</select>

<insert id="insertBlobData" parameterType="LobVo">
	insert into test_blob(user_no, user_name, blob_data, clob_data, reg_date)
	values(#{userNo}, #{userName}, #{blobData,jdbcType=BLOB}, #{clobData,jdbcType=CLOB}, #{regDate})
</insert>

<update id="updateBlobData" parameterType="LobVo">
	update test_blob set
		user_name = #{userName},
		blob_data = #{blobData,jdbcType=BLOB},
		clob_data = #{clobData,jdbcType=CLOB},
		reg_date = #{regDate}
	where user_no = #{userNo}
</update>
...

</mapper>
```

When handling LOBs, an important point to note is that Altibase requires autocommit mode to be set to false and transactions to be managed accordingly. In iBATIS integration, when dataSource is set in the <transactionManager> of the SqlMapConfig file, setAutoCommit(false) is internally called to disable autocommit, so no special consideration is needed for LOB handling. However, in MyBatis, the default is true, so it must be explicitly set when obtaining the session.

If autocommit mode is not set to false, an error like “java.sql.SQLException: [0]:LobLocator can not span the transaction 101858625.” will occur.

This error also occurs when inserting LOB data.

The following example is part of a sample that handles LOB data in MyBatis, with the full source attached in the appendix.

Example) LobMapper.xml file of altibase_mybatis_lob

```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
"http://mybatis.org/dtd/mybatis-3-mapper.dtd">

<mapper namespace="com.altibase.psy.mapper.LobMapper">
	<!-- LOB select, insert, update, delete Test - 2013/11/05 -->
	<select id="selectBlobData" parameterType="Integer" resultType="LobVo">
		SELECT user_no as userNo, user_name as userName, blob_data as blobData, clob_data as clobData, reg_date as regDate
		FROM test_blob
		WHERE user_no = #{userNo}
	</select>

	<select id="selectAllBlobData"  resultType="LobVo">
		SELECT user_no as userNo, user_name as userName, blob_data as blobData, clob_data as clobData, reg_date as regDate
		FROM test_blob
	</select>

	<insert id="insertBlobData" parameterType="LobVo">
		insert into test_blob(user_no, user_name, blob_data, clob_data, reg_date)
		values(#{userNo}, #{userName}, #{blobData,jdbcType=BLOB}, #{clobData,jdbcType=CLOB}, #{regDate})
	</insert>

	<update id="updateBlobData" parameterType="LobVo">
		update test_blob set
			user_name = #{userName},
			blob_data = #{blobData,jdbcType=BLOB},
			clob_data = #{clobData,jdbcType=CLOB},
			reg_date = #{regDate}
		where user_no = #{userNo}
	</update>

	<delete id="deleteBlobData" parameterType="Integer">
		delete from test_blob
		where user_no = #{userNo}
	</delete>

</mapper>
```

To run the above altibase_mybatis_lob project, the Altibase.jar and mybatis-3.2.8.jar files are required.

## The issue of duplicate Insert queries being sent during Insert operations

---

```
15:15:55.076 [main] [main] [ERROR] - 2. Connection.prepareStatement(insert into TB_DB_CONFIGSET_LEVEL(DB_TYPE_CODE, LEVEL_CODE, LEVEL_NAME
      )
    values (?, ?, ?
      ), 1) insert into TB_DB_CONFIGSET_LEVEL(DB_TYPE_CODE, LEVEL_CODE, LEVEL_NAME
      )
    values (?, ?, ?
      )
```

Issue Description:

- When setting 'useGeneratedKeys' to true in the MyBatis configuration XML, the problem described above occurs.

- This setting is defined as follows ([http://mybatis.github.io/mybatis-3/ko/sqlmap-xml.html](http://mybatis.github.io/mybatis-3/ko/sqlmap-xml.html)):

- It enables the use of the JDBC getGeneratedKeys method to retrieve keys generated internally by the database.

- Default value: 'false'

- Changing this setting to false prevents the issue from occurring.

- This problem does not occur with Oracle or Informix databases with the same setting.
