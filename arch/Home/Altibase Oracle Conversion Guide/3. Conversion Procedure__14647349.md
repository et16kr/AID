Use an automated tool called Migration Center for data conversion.

Before the conversion work, it is necessary to create a user and create a tablespace according to the environment used in the previous DBMS for mapping work.

When specific DB-dependent functions are applied, the manual conversion is performed.

## **Conversion Tools**

### **Migration Center**

1) Advantages of Migration Center

 East to use with GUI-based tool  Easy execution and high performance of transferring by supporting CLI mode  Transfer data along with schema in one operation  Perform migration by mapping different data types  Support user-defined formats to support flexible data migration  Provide step-by-step step summary report on conversion results

2) How to use

(1) Add Database Connection

Input the information of Source/Targe DBMS  Connection Name : Can be arbitrarily specified  IP : DBMS Server IP  Port : DBMS Server Port  User : Connected user account  Password : Connected user password  SID : Service name  IP Version : IPv4/IPv6

![trans4.png](https://docs.altibase.com/download/attachments/embedded-page/arch/3.%20Conversion%20Procedure/trans4.png?api=v2)

Since the JDBC driver is used to connect to the database, it is important to prepare a suitable JDBC driver for the source database and target database. For user convenience, several JDBC drivers suitable for supported databases are provided with the Migration Center.

(2) Create Project

Create a project for data migraiton  Project Name : Can be arbitrarily specified  Project Path : Automatically created  Source Database : Oracle  Destination Database : Altibase

![trans5.png](https://docs.altibase.com/download/attachments/embedded-page/arch/3.%20Conversion%20Procedure/trans5.png?api=v2)

(3) Build Project

Select the method (Fast/Slow) to get the number of records in the table from the source database and proceed.![trans6.png](https://docs.altibase.com/download/attachments/embedded-page/arch/3.%20Conversion%20Procedure/trans6.png?api=v2)

(4) Reconcile Project

This is the most important step in the migration process that defines how to perform the migration.

 User Mode: Defines all tables and all data accessible to the user account defined when creating the source database as migration targets  Table Mode: Select and define the table to migrate data from among all tables accessible to the user account defined when creating the source database

![trans7.png](https://docs.altibase.com/download/attachments/embedded-page/arch/3.%20Conversion%20Procedure/trans7.png?api=v2)

 Data Type Mapping: Data type mapping between Oracle and Altibase  PSM Data Type Mapping: Data type mapping between Oracle PL/SQL and Altibase PSM  Tablespace to Tablespace Mapping: Oracle and Altibase tablespace mapping  Table to Tablespace Mapping: Specify the tablespace to store Altibase tables  Select Editing: Add/edit Oracle data search condition  DDL Editing: Edit the final DDL of Altibase

**![trans8.png](https://docs.altibase.com/download/attachments/embedded-page/arch/3.%20Conversion%20Procedure/trans8.png?api=v2)**

(5) Run Project

Run the data migration.

**![trans9.png](https://docs.altibase.com/download/attachments/embedded-page/arch/3.%20Conversion%20Procedure/trans9.png?api=v2)**

(6) PL/SQL Convert Tool

Use Oracle PL/SQL saved a file using the Migration Center to change the syntax for the data type.

Change to business logic are not automatically converted and must be converted manually by the developer who implemented the business logic.
